## 1. What this project is

Website for **Mezin Food Products (MFP)**, a small food-processing business in Saravanampatti, Coimbatore, Tamil Nadu.
Visitors browse five products, add them to an **enquiry list** (not a cart, no payments), and send the list to the owner on **WhatsApp**.
The site is bilingual: **English and Tamil**. Many visitors will be on cheap Android phones, so the phone experience matters most.

Stack: Next.js 14 (App Router), React 18, TypeScript, Tailwind CSS 3.4, lucide-react, `next/font`, `next/og`, `next/image`.

The code was generated by Antigravity (Google's agent IDE). It has been reviewed and tested independently over two rounds. The owner's business facts are still incomplete (section 6).

## 2. Hard rules (never break these)

**Contact details**
- Display the phone number as `96590 87877`. Never show `+91` or `91` in visible text.
- The `91` country code appears only in links: `tel:+919659087877` and `https://wa.me/919659087877?text=<encodeURIComponent(message)>`.
- All contact details live in `src/config/site.ts` (`displayPhone`, `rawPhone`, `phoneUrl`, `whatsappBaseUrl`, address EN/TA, `mapsUrl`, `buildWhatsappUrl`). Never hard-code them in a component.

**No invented facts**
- Do not invent claims about the business: years in operation, certifications, FSSAI numbers, "100% natural", "hygienic", "healthy", "quality", "staple", delivery areas, prices, weights, awards, customer counts, testimonials.
- Do not invent a website address. There is no confirmed domain.
- If you need a fact the owner has not given, leave a clearly marked `TODO(owner)` and tell the user. Do not fill it with plausible copy.
- `scripts/check-claims.mjs` guards this. Keep it strict. Never weaken it to make a build pass.

**Tamil**
- Every visible string comes from `src/i18n/en.ts` and `src/i18n/ta.ts`, with identical keys. This includes `aria-label`s, placeholders and footers.
- No English in Tamil mode except: the brand name, "MFP", the phone number, and product names.
- Tamil body text is at least 14px. Tamil uses Noto Sans Tamil (`--font-tamil`). Do not let Tamil fall back to a system font.
- Tamil translations were written by an AI. Do not claim they are native-quality. They need review by a native speaker.

**Phone usability**
- No horizontal scroll at 320, 360, 375, 390, 412, 768, 820, 1024, 1280 and 1440px, in both English and Tamil.
- Every tappable thing is at least 44×44px (menu button, footer links, phone and WhatsApp links, card buttons).
- No text below 12px.
- The header is 64px on phones. The brand name wraps to two lines below `sm`. It is never truncated.
- Popups dim the page, lock body scroll, close with Escape, and return focus to the element that opened them.

**Data and storage**
- The enquiry list stores only product IDs in localStorage under `mfp_enquiry_ids`. Language is under `mfp_preferred_lang`. Wrap storage access in try/catch.
- The WhatsApp message is built from the product data and the current language. Never store message text.

**Code hygiene**
- Do not use a Tailwind colour class that is not defined in `tailwind.config.ts`. A missing class fails silently and gives an invisible-text bug. `scripts/check-classes.mjs` guards this.
- Do not edit files outside this project. Do not delete files without telling the user.

## 3. How to verify (do this before saying "done")

1. `npm run build` must succeed.
2. `npm run verify` (classes, claims, Tamil Latin-word check) must pass.
3. Run a **real** browser test, not just a build. Use Playwright (Chromium) at all ten widths in English and Tamil. Check `document.documentElement.scrollWidth <= window.innerWidth`.
4. Test the mobile menu at 320, 360, 390 and 412px: opens, closes, button fully on screen.
5. Open a product popup: page dims, body scroll locks, Escape closes it, focus returns to the product.
6. Add a product, open the enquiry drawer, check the WhatsApp link text in English and Tamil.
7. Scan the Tamil page text for Latin letters other than the allowed ones.
8. Report **real pass/fail output**, including failures. Never write "all checks passed" without running them.

Note: Google Fonts may be unreachable in a sandbox. If a build fails only because of that, do not change the fonts in the real project. Use a temporary copy.
